# HANDOFF: building a website from this repo

This file is written for an AI (or person) building a website on top of TrialPulse. Everything the site needs is in [`exports/`](exports/). Read the **Required display rules** before writing any UI.

## What the project is

TrialPulse ranks **currently recruiting interventional clinical trials with at least one Massachusetts site** by their predicted risk of **enrollment-related early termination**: stopping early (terminated or withdrawn) because the trial could not enroll enough participants.

- **Model:** LightGBM classifier (logistic regression kept as a baseline).
- **Training data:** registered trials from the [ClinicalTrials.gov API v2](https://clinicaltrials.gov/data-api/api).
- **Labels:** come from the free-text "why stopped" field. A keyword rule marks accrual/enrollment/recruitment reasons as positive, and completed trials are negative.
- **Features:** design-time only (phase, sponsor type, number of sites, eligibility rules and similar). Nothing known only after a trial runs is used.
- **Split:** trained on trials that started 2008–2018, tested on trials that started 2019–2021. There is no random split.
- **Output:** a probability per trial, plus a rank, a tier and the three features that pushed that trial's score most.

It is a prioritization aid for recruitment offices: *which trials might need outreach help?* It is not a judgment of a trial's science, and it never looks at patients.

## Required display rules

These are hard requirements. A site that breaks any of them misrepresents the project.

1. **Cite the source with every number.** Any risk score, count, percentage, metric or chart must carry "Source: ClinicalTrials.gov" (the exports say "ClinicalTrials.gov API v2"; either wording is fine), e.g. as a caption or footnote on the same card, table or chart.
2. **Say what is predicted, exactly.** The model predicts *enrollment-related early termination* only. Never describe it as predicting trial "success", "failure" of a treatment, efficacy, safety or quality. Good: "risk of stopping early due to low enrollment". Bad: "chance this trial succeeds".
3. **It ranks trials, never people.** Do not build any feature that scores, matches, screens or recommends trials for a patient, whether named, anonymous or hypothetical. No "find trials for me", no symptom or eligibility questionnaire, no patient profile.
4. **Every trial view must:**
   - link to its ClinicalTrials.gov page (`url` field);
   - display the sentence **"Eligibility is decided by the study team."**;
   - display the sentence **"Not medical advice."**
5. **Eligibility text is verbatim.** Show `eligibility_criteria` exactly as provided (preserve line breaks; render as preformatted or simple Markdown). Never summarize, paraphrase, translate or rewrite it with an LLM or anything else. Trimming with a "show more" toggle is fine; changing words is not.
6. **Show the limits** (below) somewhere reachable from every page, e.g. an "About the model" page linked in the footer.
7. **Risk is an estimate.** Present scores as estimates (e.g. "30% estimated risk"). Even in the high tier, most trials are expected to finish normally.

## Files in `exports/`

All JSON is UTF-8 with no NaN; missing values are `null`. Regenerated by `make export` (see [How to regenerate](#how-to-regenerate)).

### `exports/ma_trials.json`

An array with one object per scored trial, **sorted by `risk` descending** (`risk_rank` 1 = highest). It covers recruiting, interventional trials with at least one listed Massachusetts site. It is about 12 MB because it includes the full eligibility text, so **load it only for trial detail views** and use `ma_trials_index.json` for lists, tables, maps and search.

| Field | Type | Meaning |
|---|---|---|
| `nct_id` | string | ClinicalTrials.gov ID, unique, e.g. `"NCT04206215"` |
| `title` | string | Brief title as registered |
| `url` | string | `https://clinicaltrials.gov/study/<nct_id>`; link to it from every trial view |
| `risk` | number 0–1 | Predicted probability of enrollment-related early termination, 4 decimals |
| `risk_rank` | integer ≥ 1 | 1 = highest risk; ranks are 1..n in file order |
| `risk_percentile` | number 0–100 | % of scored trials with risk ≤ this trial's, rounded down to 1 decimal (only the top trial is 100.0) |
| `risk_tier` | `"high"` \| `"elevated"` \| `"typical"` | Tiers by rank: `high` = top 10% (ranks 1–262 in the current export, risk ≥ 0.1293), `elevated` = next 20% (ranks 263–786, risk ≥ 0.0720), `typical` = remaining 70%. High covers ranks 1 to ⌈0.1·n⌉ and elevated the next ⌈0.2·n⌉. Current cutoffs are always in `summary.json` → `risk_tiers` |
| `risk_vs_typical` | number | `risk` / median risk of all scored trials, 1 decimal (e.g. `2.8` = 2.8× the typical trial) |
| `phases` | string[] | e.g. `["PHASE2"]`, `["PHASE1","PHASE2"]`, `["NA"]` (not applicable, e.g. device/behavioral); may be empty |
| `sponsor_class` | string \| null | Lead sponsor type: `INDUSTRY`, `OTHER` (academic/other), `NIH`, `FED`, `OTHER_GOV`, `NETWORK`, `INDIV`, … |
| `conditions` | string[] | Conditions as registered |
| `condition_categories` | string[] | Top-level MeSH disease categories derived by ClinicalTrials.gov (e.g. `"Neoplasms"`); may be empty |
| `n_sites` | integer | Number of listed locations worldwide |
| `n_ma_sites` | integer ≥ 1 | Number of listed Massachusetts locations |
| `ma_sites` | object[] | Massachusetts sites only: `{facility: string\|null, city: string\|null, lat: number\|null, lon: number\|null}`; length = `n_ma_sites` |
| `min_age` | string \| null | As registered, e.g. `"18 Years"`; `null` = no minimum |
| `max_age` | string \| null | As registered; `null` = no maximum |
| `sex` | string \| null | `ALL`, `FEMALE` or `MALE` |
| `healthy_volunteers` | boolean \| null | Whether healthy volunteers are accepted |
| `start_date` | string \| null | `YYYY-MM` or `YYYY-MM-DD` |
| `top_reasons` | object[3] | The 3 features that moved this trial's score most (per-trial SHAP), largest first, **excluding site country** (see below): `{feature_label: string, direction: "raises risk"\|"lowers risk", plain_english: string}`. `feature_label` names the model input (e.g. "Number of trial sites"); `plain_english` describes this trial's value (e.g. "1 trial site listed") |
| `eligibility_criteria` | string \| null | Verbatim eligibility text from the registry; **display unchanged**. It is the registry's Markdown-style text (`*` bullets, `\n` line breaks, escapes such as `\<`), so render it as Markdown or show it preformatted |

`top_reasons` explain the model, not the trial. Present them as "why the model scored it this way", not as advice to the study team. Two caveats:
- **Site country is never a reason.** The model uses it, but it mostly reflects how consistently US-regulated trials report a stop reason, not anything about a trial's design. It is skipped and the next feature is used, so every trial still has 3 reasons.
- **"Rare-disease keywords in condition"** is a keyword match on condition names ("rare", "orphan"). It is not a clinical rare-disease designation and flags very few trials, so never label a trial "rare disease" because of it.

### `exports/ma_trials_index.json`

Exactly the records of `ma_trials.json`, in the same order, **without `eligibility_criteria`** (about a third of the size). Use it for list pages, tables, maps, filters and search. Fetch `ma_trials.json`, or that record's eligibility text, only when a single trial's detail view opens.

| Field | Type | Meaning |

The headline row is `population=all, scheme=strict, slice=all, model=lightgbm`. For Massachusetts, use `slice=ma`, but note it is small (about 1,700 test trials, under 100 positives).

### `exports/feature_importance.json`

Global drivers of the default model. `features` is an array of 15 entries, `{rank: int, feature: string (technical name), label: string (plain English, show this), mean_abs_shap: number}`, measured as mean |SHAP| on the test set in log-odds units. Higher means the feature moves scores more, in either direction.

"Main site in the US" (`Site country: United States`) appears here because the model uses it. If you show it, say that it reflects how consistently US-regulated trials report why they stopped, not trial design. It is never shown as a per-trial reason.

## How to regenerate

```bash
make setup     # once: .venv + dependencies (macOS: brew install libomp first)
make all       # data -> train -> report -> slides -> export
```

`make all` runs, with timings measured on a laptop:

| Step | What it does | Time |
|---|---|---|
| `make data` | Pulls ~387k trials from the ClinicalTrials.gov API v2 (`fields=`, `pageSize=1000`) into `data/raw/` (gitignored) | ~6.5 min |
| `make train` | Labels, features, both models × schemes × populations, metrics, SHAP, scores the recruiting MA trials | ~30 s |
| `make report` | Ranked CSV in `data/processed/` | < 1 s |
| `make slides` | Slide figures in `figures/slides/` | ~2 s |
| `make export` | Writes and validates `exports/` | ~2 s |
| **Total** | | **~7 min** |

To refresh only the exports from existing data: `make train report slides export`. `make export` fails loudly if any validation check fails: field types, no NaN, unique `nct_id`, ranks 1..n, risk non-increasing with rank, tier counts, no site-country reasons, index identical to the full file minus eligibility text, figures present.

## Known limits

Show these on an "About the model" page. They come from the [README](README.md) and the original [idea brief](docs/idea_brief.md).

- **Labels come from free text.** "Why stopped" is optional and free-form. A keyword rule classifies it, so some labels are wrong. The hand-check agreement is still pending (`label_handcheck_agreement: null`). Reasons that mix low enrollment with another cause (e.g. funding) are excluded, not counted.
- **Retrospective registrations are excluded.** Trials first registered more than 30 days after they started are dropped from training and testing: 38% of trials. A trial registered after it has run is almost always already finished, so it leaks the outcome. Removing this leak lowered test AUC from 0.791 to 0.763.
- **Observational studies are out of scope.** Only interventional trials are modelled and scored.
- **The model is national and applied to Massachusetts.** It is trained on trials from all countries. On held-out trials with a Massachusetts site it does slightly worse (AUC about 0.75), and that slice is small (about 1,700 test trials, under 100 positives).
- **Some trial types are weaker.** Accuracy is lower for mental-health trials (AUC about 0.63 on test trials in the MeSH "Mental Disorders" category).
- **Rare diseases cannot be evaluated.** The registry data has no reliable rare-disease marker. The keyword flag ("rare", "orphan") matches 17 of about 112,000 modelling trials, and the MeSH term "Rare Diseases" only 27. So we make no claim about rare-disease performance.
- **Reporting differences.** "Main site in the US" raises risk partly because US-regulated trials fill in the stop reason more consistently, so their low-enrollment stops are more often labeled. That is a reporting effect, not evidence that US sites recruit worse, and it is why site country is never shown as a per-trial reason.
- **The rare-disease feature is a keyword match** on condition names ("rare", "orphan"). "Syndrome" was removed because it flagged common conditions such as carpal tunnel syndrome.
- **Survivorship.** Trials that were never registered are invisible to the data.
- **What the data cannot see:** recruitment through networks not listed as sites, stop reasons never entered, protocol quality and investigator track record.
- **Scores are probabilities, not verdicts.** Even among the riskiest 10%, most trials are expected to finish normally.
- **About 15–20% of trials have no MeSH condition terms,** so `condition_categories` can be empty.
